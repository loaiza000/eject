# Architecture

The entry point `cmd/eject` translates process signals and errors into exit status. `internal/cli` constructs Cobra commands, reads the versioned IR and writes user output. `internal/discovery/aws` validates a versioned manifest and parses selected exported AWS CLI responses. `internal/domain` defines versioned IR, compatibility and plan records. `internal/compatibility` evaluates explicit Compose rules; `internal/planner` turns results into an unexecuted proposal. Command construction is isolated to make it testable without global mutable state.

The implemented flow is manifest → AWS parser → versioned neutral IR → compatibility rules → migration proposal → Compose proposal → verification. `internal/generator` recalculates Phase 2 results, embeds the plan, and writes a completion marker. `internal/verification` compares all files with a fresh rendering, then optionally checks a local Docker runtime with explicit authorization. AWS remains an input adapter; Compose is a target assessed by rules, not the domain model.

`inspect` records only dependencies directly present in snapshots. It deliberately does not infer connections from environment variable names or endpoint similarity. No network or cloud account is needed for static operations; `generate` and static `verify` invoke only local Docker Compose `config` when available. Runtime verification uses a random project name and fixed Docker commands. `doctor` checks executable lookup only.

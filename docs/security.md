# Security

`inspect` reads local files capped at 1 MiB and 64 JSON nesting levels each. It opens files relative to an `os.Root` directory handle and rejects traversal and symlinked input paths. The manifest parser rejects unknown fields and versions. AWS response parsers read only selected fields; ECS environment values and secret references are discarded. JSON output writes use restrictive permissions and refuse existing files unless `--force` is provided. EJECT does not execute AWS commands or perform telemetry. `doctor` only searches `PATH` for a Docker executable; `generate` runs local `docker compose config` when available.

Input complexity is bounded by file size, nesting depth, and manifest entry count. `plan` accepts a local IR file of at most 8 MiB and 64 JSON levels, rejects unknown JSON fields and symlinked input files, and never executes content from it. It carries variable names, not ECS values or secret references, into reports. New JSON output uses a same-directory temporary file and a hard link that fails if a destination appears concurrently; a filesystem that cannot create hard links returns an error. With `--force`, EJECT syncs the temporary file and renames it over an existing regular file. This avoids deleting the old file first. Go documents that rename is not guaranteed atomic on non-Unix platforms, including Windows; filesystem and power-loss behavior also vary.

`generate` accepts version 2 plans up to 32 MiB and 64 JSON levels, rejects unknown fields and symlinked plan files, recalculates all rules and steps, and restricts generated property names, image references, variable names and ports. It never executes plan content. New output directories and files request mode 0700/0600 on Unix. On Windows, the newly created empty project directory receives a protected DACL before EJECT writes any contents; new output and temporary files receive protected DACLs at creation. These DACLs allow the current user, LocalSystem and Administrators. EJECT never changes the ACL of an existing parent directory. Identical existing generations are accepted only if their directory and files pass the Windows ACL check; legacy permissive generations must be recreated in a new directory. The check is deliberately conservative and may reject custom ACLs. It cannot prevent privileged local processes, a later ACL change or exposure through copies. Changed or extra files and symlinked output paths are rejected. There is no overwrite flag. Generated directory writes are not atomic as a group. The command invokes local `docker compose config` when available, without starting containers. It does not send data to AWS or a hosted service.

`generate` writes `plan.json` and a hashed `generation.json` completion marker. Static `verify` recalculates the project and detects missing, altered, or extra files without starting containers. These hashes are unkeyed consistency checks, not signatures or proof of origin: someone able to replace the embedded plan and all generated files can create a different self-consistent project. Review provenance and the plan separately before authorizing runtime execution. EJECT does not inspect private `.env` values; on Windows it checks their ACL before runtime. Runtime verification requires `--allow-start`; image downloads additionally require `--allow-pull`. A random Compose project isolates containers. EJECT runs fixed Docker commands, uses timeouts, and stops only that project without deleting named volumes. Container images are executable code; use runtime verification only with images you trust. The static credential scan is heuristic and cannot establish the absence of all secrets.

Do not put credentials in issue reports or example snapshots.

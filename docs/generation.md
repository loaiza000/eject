# Compose generation

`eject generate --plan plan.json --output ./output` accepts a version 2 Compose plan from `eject plan`. Version 1 plans lack the source metadata needed for generation and are rejected with instructions to rerun `plan`. The command recalculates compatibility results and steps from the embedded inventory; changed statuses, steps or source fields cannot silently alter the output.

For eligible resources, `compose.yaml` contains ECS container image references, internal container ports (`expose`), a local bridge network, and empty local PostgreSQL 16 Alpine services with named volumes and a fixed `pg_isready` health check. Other PostgreSQL major versions are blocked until their image layout is validated. Container environment variable *names* use required local placeholders. EJECT does not publish host ports, infer ECS-to-RDS links, copy values or secrets, map IAM, reproduce ECS scheduling, or migrate RDS data. ECS health checks are not captured by current snapshots and are not generated. The PostgreSQL image tag uses the recorded major version only; verify tag availability, patch version, extensions and settings.

S3 has no generated service or bucket mapping. The current compatibility rules have no verified local S3-compatible backend, object inventory, IAM or policy translation. `limitations.json` records the manual work.

The output status is `BLOCKED` when no service can be rendered, `PARTIAL` when at least one service can be rendered but blockers, manual actions, exclusions or incomplete compatibility remain, and `COMPLETE` only when all recorded capabilities are fully supported and represented. Current ECS and RDS rules retain partial or manual findings, so a complete status is not expected for those workloads. Every output contains `README.md`, `limitations.json`, embedded `plan.json`, and a hashed `generation.json` completion marker written last. Eligible outputs also contain `compose.yaml` and `.env.example`. The report lists included and excluded source IDs, blockers, manual actions and limitations. It never claims data or runtime equivalence.

The command creates a new output directory with restrictive permissions. Repeating generation against an identical directory succeeds without rewriting it; changed or extra files, symlinks and non-directory targets cause an error. It never offers `--force`. Directory creation and multi-file writes are not an atomic bundle; an interrupted process may leave an incomplete directory. An interrupted or failed run may leave a directory without `generation.json`; `eject verify` reports it as incomplete. Inspect and remove that directory manually before retrying. Do not run two generators against the same output path concurrently.

Generated YAML is parsed locally. When the Docker Compose plugin is available, EJECT also runs `docker compose -f compose.yaml config --no-interpolate --quiet` before reporting success. This command does not start containers or connect to AWS. Validation checks Compose syntax, not image availability, application behavior, data or deployment equivalence. If Docker Compose is absent, only local YAML parsing is performed.

Review `limitations.json` and the generated README before running Docker. Supply required values privately; `.env.example` intentionally contains empty values and must not be used as a secret store.

# Verification

`eject verify --project ./output` emits a version 1 JSON report. Each check is `PASSED`, `FAILED`, `SKIPPED`, or `NOT_VERIFIED`; `outcome` is `FAILED` if any check failed. The report also carries the generation status (`PARTIAL`, `BLOCKED`, or `COMPLETE`). A passed static report means the generated files match the embedded plan and Docker Compose accepts their syntax when available. It does not mean the application works or that AWS behavior and data were reproduced.

Static verification is offline and does not start containers. It reads the embedded version 2 plan, recalculates compatibility and steps, regenerates expected files, and compares every byte of the project. `generation.json` is written last during generation and records hashes; a missing, unreadable, or changed marker reports an incomplete or modified generation. The marker is an unkeyed consistency check, not proof of origin; a fully replaced, self-consistent project can pass. Extra files are rejected except a private `.env`, whose values are never read or printed by EJECT. On Unix, `.env` must exclude group and other permissions. Windows ACL confidentiality is reported as `NOT_VERIFIED` because inherited ACEs may grant additional access. Secret scanning checks generated files for common credential patterns and cannot prove the absence of every secret. Docker Compose `config --no-interpolate --quiet` runs only if the plugin is installed.

`eject verify --project ./output --runtime` first runs static checks. It reports `SKIPPED` until the operator supplies `--allow-start`; this flag explicitly authorizes local container startup. By default `docker compose up` uses `--pull never` and `--no-build`. `--allow-pull` separately permits downloads of missing images. Runtime verification uses a random Compose project name, a two minute overall timeout, and `up --wait` to check health. It checks running containers and health status, then runs fixed PostgreSQL `pg_isready` and `SELECT 1` probes. It stops only its own Compose project with `down --remove-orphans`; it never uses `down -v` and retains named volumes. The report includes the project name for manual inspection. It does not contact AWS.

An optional `--http-check service:port:/path` checks an exposed TCP container port. The verifier adds a temporary loopback-only, dynamically assigned host port to its isolated Compose project, sends a bounded HTTP GET, and removes the temporary override. The service and port must already appear in the verified generated Compose file. The path is restricted to a small safe character set. This checks one endpoint response, not functional equivalence.

Runtime checks may fail because of missing local images, unavailable Docker, missing values in a private `.env`, unhealthy services, or permission errors. Failure details do not include Docker output or secret values. Cleanup failures are reported explicitly, including the isolated project name. Do not use runtime verification against untrusted container images: authorization to start a service also authorizes execution of that image's entrypoint.
